# 바이낸스 자동매매

바이낸스 상품 조회와 USDT 선물 조건식 자동매매 앱입니다.

**[Windows 다운로드 · v0.4.72](https://github.com/bhb414/binance-tradingbot-ko/releases/download/v0.4.72/binance-tradingbot-ko-v0.4.72-windows.zip)** · [최신 릴리즈](https://github.com/bhb414/binance-tradingbot-ko/releases/latest)

[소스 코드 ZIP](https://github.com/bhb414/binance-tradingbot-ko/archive/refs/heads/main.zip)

차트의 **라벨** 메뉴에서 우측 지표 이름·현재가·진입 평단 표시를 각각 켜고 끕니다. 선과 계산은 유지하고 라벨만 숨기며, 서버에 저장해 다른 기기와 접속 주소에서도 복원합니다.

사용자 지표는 `막대("이름", 수식, 색기준식)`으로 막대를 표시합니다. 색기준식 생략은 0이며 수식·앞에서 정의한 변수를 사용할 수 있습니다. 스타일의 **기준 이상 색상 / 기준 미만 색상**을 선택하세요. 같은 값은 기준 이상 색상, 기준식이 미수집인 봉은 빈 값입니다. 막대 높이는 0부터 원값까지이고 색기준식은 색 판단에만 사용합니다. 막대 입력 시 별도 패널로 자동 배치합니다.

## 실행

1. [Node.js 24 이상](https://nodejs.org/en/download)을 설치합니다.
2. 다운로드한 ZIP을 모두 풀고 **run.cmd**를 실행합니다.
3. 설정에서 본인 API 키를 등록하고, 주문 허용을 켠 뒤 봇을 시작합니다.

Windows용입니다. 별도 npm 설치는 필요 없습니다. 주소는 http://127.0.0.1:8896 입니다.

실행 창이 바로 닫혔던 이전 버전 사용자는 v0.4.35 ZIP을 새 폴더에 전부 풀어서 실행하세요. Windows 명령 파일의 줄바꿈을 수정했습니다. 실행 실패 시 창을 유지하고 `startup-error.log`에 오류를 남깁니다. 기존 폴더를 업데이트하려는데 update.cmd도 닫힌다면, 프로그램 종료 후 그 폴더에서 터미널을 열고 `node tools/update.mjs`를 실행하세요.

## 봇 목록의 보유 포지션

각 봇의 이름 아래에서 보유 종목·롱/숏·수량·진입평단을 바로 확인합니다. 같은 종목을 여러 봇이 매매하더라도 해당 봇에 배정된 수량과 평단을 표시합니다. 다중종목 봇은 보유한 각 종목을 나누어 표시하고, 정지 상태의 보유분도 표시합니다.

## 계좌 전체 잔고 추이

그래프의 가로축은 실제 경과 시간입니다. 과거 일별 지갑 기록은 점선·원, 직접 관측한 지갑·평가 기록은 실선으로 구분하고 미수집 구간은 연결하지 않습니다. **전체 기록 / 상세기록 확대**, 드래그 이동과 +/− 확대를 지원합니다. 이 브라우저에서 보던 전체·상세·직접 확대 범위는 새로고침 후 복원합니다. **앞으로 저장할 기록 주기**는 미래 수집 간격이며 기존 기록을 재계산하거나 같은 봉 간격으로 재배치하지 않습니다.

홈의 **계좌 추이** 또는 기록 화면의 **계좌 잔고 추이**에서 USDT 선물계좌 전체를 조회합니다. 지갑 잔고(실현손익·이미 반영된 수수료·펀딩 포함)와 평가잔고(지갑 잔고 + 현재 미실현손익)를 두 선으로 표시합니다. 수동 거래와 모든 봇의 거래를 포함하며 봇 예산과는 별개입니다. 현물·COIN-M·USDC 자산은 합산하지 않습니다.

그래프 위에 전체 기록의 시작 시각과 이전 기록 유무를 표시합니다. 저장된 기록이 모두 보이는 경우 **이전 기록 없음**으로 안내합니다. 처음 열 때 저장된 구간을 화면에 맞추고, 지갑 잔고는 파란 실선과 마지막 저장 금액으로 구분합니다.

기간 필터 대신 **기록 주기**를 설정합니다. 기본 1분이며 5초~1일 사이를 직접 입력할 수도 있습니다. 주기를 바꿔도 기존 관측값은 유지하고, 그래프를 이동·확대하거나 이전 기록을 불러볼 수 있습니다. 설정과 기록은 서버에 저장하므로 같은 서버에 접속하는 PC·휴대폰에서 공유합니다.

상세 평가잔고 기록은 기능 적용 후부터 시작합니다. 서버가 켜지고 계좌·시세가 확인되는 동안 브라우저를 닫아도 기록됩니다. 앱 종료·연결 중단 시간과 기록 시작 이전의 미실현손익은 소급해서 채우지 않습니다. 설정한 주기의 관측은 기존 계좌 정보와 마크가격 수신값을 사용하므로 바이낸스 REST 호출을 추가하지 않습니다.

**바이낸스 과거 불러오기**를 누르면 최근 한 달에 제공된 일별 USDT 선물 지갑잔고를 가져와 직접 기록 시작 전 구간에 붙입니다. 가져온 과거 기록은 서버에 계속 보관합니다. 과거 일별 지갑잔고에는 당시 평가잔고·미실현손익을 생성하지 않습니다. 바이낸스의 일별 API는 당시 장중 미실현손익을 제공하지 않으므로 평가잔고 곡선은 직접 관측한 구간부터 표시합니다. 과거 조회는 선물 주문과 별도의 SAPI 요청으로 실행하고 6시간 동안 결과를 재사용합니다. 30일보다 오래된 미수집 기록은 이 API로 가져올 수 없습니다.

입출금·계정 간 이체도 실제 잔고에 반영됩니다. ‘첫 기록 대비 변화’는 자금 이동을 포함한 잔고 변화이며 순수 매매 수익률이 아닙니다. 미실현손익에는 아직 발생하지 않은 정리 수수료·향후 펀딩을 미리 빼지 않습니다. 계좌 API 키 식별별로 기록을 분리하며, 기록은 **.runtime/account-equity.sqlite**에 보존됩니다. 프로그램을 종료한 후 .runtime 폴더 전체를 함께 보관하세요.

**Cannot find module**처럼 프로그램 파일이 없다는 오류가 계속 나오면 [전체 파일 복구 ZIP · v0.4.72](https://github.com/bhb414/binance-tradingbot-ko/releases/download/v0.4.72/binance-tradingbot-ko-v0.4.72-repair.zip)을 받으세요. 프로그램을 종료하고, ZIP의 **repair.cmd와 repair.ps1 두 파일을 run.cmd 옆에 넣은 뒤 repair.cmd를 실행**합니다. Git은 필요 없습니다.

복구 도구는 문제가 난 앱 모듈을 사용하지 않고 공식 배포본을 별도로 받아 검증합니다. 누락·변경된 프로그램 파일 전체를 복구하고 적용 전에 원본 소스를 .runtime/backups에 백업합니다. API 키·봇·매매 기록·차트·즐겨찾기 등 저장 데이터와 개인 추가 파일은 보존합니다. 완료 후 run.cmd로 실행하세요. 정상 설치에서도 repair.cmd로 전체 프로그램 파일을 검사·복구할 수 있습니다.

## 기기 간 즐겨찾기 공유

종목 검색의 별 목록은 서버의 **.runtime/favorites.json**에 저장합니다. PC·같은 Wi-Fi·휴대폰에서 같은 목록을 사용하며, 종목 검색을 열거나 화면으로 돌아올 때 동기화합니다. 목록을 열어 둔 동안에도 서버의 로컬 저장 목록을 확인하며 추가 바이낸스 조회는 하지 않습니다. **동기화** 버튼으로 직접 다시 불러올 수도 있습니다.

기존 기기는 업데이트 후 한 번씩 새로고침하면 그 브라우저에 저장했던 즐겨찾기를 공통 목록에 합칩니다. 원래 브라우저 목록은 별도 백업 키에 보존합니다. 이전 목록은 한 번만 가져오며, 서버에서 명시적으로 삭제한 별은 다른 기기의 오래된 목록에서 되살리지 않습니다. 사용자가 별을 직접 다시 누르면 추가할 수 있습니다.

종목별 추가·삭제만 반영하므로 동시에 다른 별을 바꿔도 전체 목록을 덮어쓰지 않습니다. 현물·선물 등 시장별 식별자를 구분하고, 빈 목록도 그대로 유지합니다. 저장 실패 시 성공으로 표시하거나 기존 목록을 덮어쓰지 않습니다. 서버 재시작·업데이트에도 파일을 보존합니다.

## 수식 편집과 함수 도움말

자동완성은 커서 앞에 입력한 부분만 완성합니다. 커서 뒤의 함수 인수·조건·@주기·[봉 번호]는 보존하며, 이미 있는 함수명 뒷부분과 괄호를 재사용합니다. 입력·커서가 바뀐 오래된 후보는 적용하지 않습니다. 자동완성 선택은 ↑↓ 뒤 Enter, Tab 또는 목록 터치로 하며, 선택하지 않은 상태의 Enter는 줄바꿈합니다. 함수 삽입은 기본 실행 취소(Ctrl+Z)를 지원합니다.

괄호·대괄호 짝을 자동 입력하고, 이미 있는 닫는 괄호를 누르면 그 뒤로 이동합니다. 빈 괄호에서 Backspace는 괄호 한 쌍만 지웁니다. 도움말은 커서가 있는 가장 안쪽 함수의 현재 인수를 작은 툴팁으로 보여줍니다. 알 수 없는 안쪽 함수를 입력 중이면 바깥 함수 도움말을 대신 띄우지 않습니다. 한글 조합과 모바일 키보드의 표시 영역을 고려합니다.

## 가정한 다음 봉의 지표·조건

**다음봉(계산식, 시가식, 고가식, 저가식, 종가식, 거래량식 선택)**은 사용자가 지정한 일반 OHLC 1봉을 더한 지표·조건 결과를 현재 시점에 계산합니다. 각 입력은 숫자 또는 현재·과거 데이터 수식입니다. 실제 미래 봉을 조회하거나 가격을 예측하는 기능이 아닙니다. 하이킨아시는 가정한 일반 OHLC와 이전 하이킨 봉으로 다시 계산합니다.

예: **다음봉(SMA(하이킨종가, 6), 종가, 최대(종가, SMA(하이킨종가, 6)), 최소(종가, SMA(하이킨종가, 6)), SMA(하이킨종가, 6))**. 다음 시가를 현재 종가, 다음 종가를 현재 하이킨 6이평으로 두고 고가·저가는 두 가격을 감싸게 가정한 뒤, 그 다음 봉의 하이킨 6이평을 현재 차트에 표시합니다. 홈 → 지표 → 새 수식 지표의 예제에서 선택할 수 있으며 데이터·함수 메뉴와 자동완성은 다음봉()만 삽입합니다.

고가는 시가·종가 이상, 저가는 시가·종가 이하여야 합니다. 거래량은 0 이상이며 생략하면 다음 거래량이 미확인이라 VWMA 등도 미확인일 수 있습니다. 봇에서는 함수 전체 뒤에 @1m처럼 주기를 붙입니다. 함수 뒤 [1]은 직전 봉 시점의 가정 결과이며 실제 다음 봉 결과가 아닙니다. 계산식은 한 종목을 대상으로 하며 A.종가처럼 지정한 종목도 지원합니다. 여러 종목의 가정 결과는 함수 밖에서 조합하고 다음봉 안의 다음봉 중첩은 지원하지 않습니다. 기존 봇·지표는 자동 변경하지 않습니다.

## VWMA와 수식 자동완성

홈 → 지표에서 **거래량 가중이동평균 · VWMA**를 추가합니다. 기간·가격 소스·일반/하이킨아시·색상·선 굵기·표시 범위를 설정합니다. 수식은 **VWMA(하이킨종가, 6)**처럼 사용하며 최근 N봉의 가격 × 거래량 합계 ÷ 거래량 합계입니다. 거래량 합계가 0이거나 데이터가 누락되면 빈 값입니다. 일별 누적 VWAP과는 다릅니다.

봇 조건은 **VWMA(하이킨종가, 6)@1m[1]**처럼 함수 전체 뒤에 주기·봉 번호를 지정합니다. A.종가를 쓰면 A의 거래량을 사용하며, 여러 종목을 조합한 데이터에는 **VWMA(A.종가/B.종가, 6, A.거래량)**처럼 세 번째 인수로 거래량을 지정합니다.

단일·다중종목 조건식과 지표식에서 입력 중 데이터·함수를 자동완성합니다. ↑↓로 선택하고 Enter/Tab 또는 목록 터치로 입력합니다. Ctrl+Space로 목록을 열고 Esc로 닫습니다. 한글 조합 중에는 선택 키를 가로채지 않습니다. **데이터·함수 추가**는 종가나 SMA()처럼 이름·빈 함수만 삽입하며 예제 인수·@주기·[봉 번호]를 자동으로 붙이지 않습니다. 함수는 괄호 안에 커서를 놓고 인수 도움말을 표시합니다. 예제 불러오기와 전체 주기 적용은 별도 명시적 기능입니다.

## 중첩 수식 계산

SMA·표준편차·볼린저밴드는 같은 봉의 계산 결과를 재사용하고 창이 이동할 때 바뀐 부분만 갱신합니다. NW를 넣은 볼린저밴드나 이평과의 차이를 다시 표준편차로 계산하는 수식도 지원합니다. 계산 한도를 높이거나 수식을 단순화하지 않고 반복 계산을 줄였습니다. 진행봉 갱신 시에는 새 데이터로 다시 계산하며 미래 봉으로 과거 값을 고치지 않습니다.

차트는 최대 5,000봉이며 계산량 제한은 유지합니다. 한도를 초과한 지표는 계산을 중단하고 지표 계산량 오류를 표시합니다. 수식의 의미·기간·저장된 차트와 봇 설정은 자동으로 변경하지 않습니다.

## 조건 발생 횟수

조건·행동의 수식에서 **발생(조건, 최근 봉 수, 최소 횟수, 최대 횟수)**를 사용합니다. 최소·최대는 모두 포함하며, 최대를 생략하면 최근 봉 수가 됩니다. 예: 발생(조건, 10, 3)은 최근 10봉에서 최소 3봉이 참인지 확인합니다. 조회 봉 수는 1~500, 횟수는 0~조회 봉 수 정수입니다.

- **발생횟수(조건, 봉 수)**: 조건이 참인 봉 수를 숫자로 반환합니다. 3봉 연속 참이면 3회입니다.
- **발생(조건, 봉 수, 최소, 최대)**: 그 개수가 범위 안이면 참입니다.
- **신규발생횟수(조건, 봉 수)**: 거짓→참으로 바뀐 봉만 셉니다. 이전부터 계속 참인 구간은 새 발생이 아닙니다.
- **신규발생(조건, 봉 수, 최소, 최대)**: 새 발생 개수가 범위 안인지 확인합니다.

예: **발생(상향돌파(하이킨종가, 볼린저상단(하이킨종가, 55, 1.04)), 10, 1, 3)@1m[1]**은 직전 완성봉부터 10개 1분봉 중 상향돌파가 1~3회 있었는지 확인합니다. 전체 뒤의 [1]을 생략하면 현재 진행봉부터 셉니다. 상향·하향 돌파는 돌파한 봉에서만 참입니다. 조건 감시를 여러 번 해도 같은 봉이 중복 집계되지 않으며 주문·체결 횟수를 뜻하지 않습니다.

단일·다중종목 조건식과 차트 수식 지표에서 지원합니다. 다중종목은 A.종가·B.종가 등을 조합할 수 있습니다. 발생 함수 전체에 @봉주기를 지정하고 함수 안에서 서로 다른 봉주기를 섞지 않습니다. 현재 시각·현재 포지션은 봉별 이력이 없으므로 발생 함수 안에 넣지 않고 바깥에서 AND·OR로 조합합니다. 호환용 수익률·평균 진입가도 실제 과거 포지션 이력이 아니므로 발생 함수 안에서 사용하지 않습니다. 조회 구간의 봉이나 조건 계산값이 없으면 결과를 미확인으로 유지합니다. 신규발생은 구간 첫 봉 직전의 참·거짓도 알아야 합니다.

+ 데이터·함수와 예시 불러오기에 추가했고, 함수 인수 도움말에서 의미를 확인합니다. 기존 봇 조건·재실행·주문 설정을 자동으로 변경하지 않습니다. 발생 조건이 여러 봉 동안 참으로 유지될 수 있으므로 주문 재실행은 기존 규칙을 따릅니다.

## 일목·미래 예상선·간단 스크립트

홈 → 지표에서 **일목균형표**와 **이평 돌파 예상**을 추가합니다. 일목은 기본 9·26·52봉, 선행·후행 표시는 26봉입니다. 이평 예상은 하이킨 종가의 VWMA 6과 SMA 55를 기본으로 사용하고, 최근 3봉 기울기를 직전 완성봉에서 3봉 뒤까지 연장합니다. 예상 범위에서 두 선이 만나는 시점을 표시하며 돌파 확률이나 실제 미래 가격은 아닙니다. 진행봉 기준도 선택할 수 있습니다.

기존 한 줄 수식 지표는 그대로 사용합니다. **지표 → ＋ 새 스크립트**를 열면 다음처럼 변수와 여러 선을 작성할 수 있습니다. 예제 선택으로 시작하고 숫자만 바꿔도 됩니다.

    단기 = VWMA(하이킨종가, 6, 거래량)
    장기 = SMA(하이킨종가, 55)
    선("단기", 단기)
    선("장기", 장기)
    예상선("단기 예상", 단기, 3, 3)
    예상선("장기 예상", 장기, 3, 3)

예상선의 세 번째 인수는 예상 봉 수, 네 번째는 기울기를 비교할 과거 봉 수입니다. 마지막 기준봉을 생략하면 1(직전 완성봉)이고, 예상선("이름", 수식, 3, 3, 0)은 진행봉에서 미래 3봉으로 그립니다. 선("이름", 수식, 26)은 계산값을 오른쪽 26봉에 표시하고 음수 이동은 왼쪽으로 표시합니다. 표시 이동은 수식에 미래 데이터를 넣는 기능이 아닙니다.

조건(판단, 참일 때 값, 거짓일 때 값), 최고(데이터, 봉수), 최저(데이터, 봉수)를 조합할 수 있습니다. 예: 선택선 = 조건(단기 > 장기, 단기, 장기). //로 설명을 남깁니다. 최대 8,000자·변수 24개·선 6개이며, 현재 차트의 봉 주기를 사용합니다. 목록에 저장한 스크립트는 PC·휴대폰에서 함께 불러옵니다.

## 내 지표 목록

**지표 → ＋ 새 수식 지표**에서 이름·수식·스타일·표시 위치를 정한 뒤 **목록에 저장**합니다. **내 지표**에서 이름 또는 ＋를 눌러 차트에 추가하고 같은 지표를 여러 개 추가할 수 있습니다. 목록은 최대 50개, 현재 차트는 기본·수식 지표를 합쳐 최대 12개입니다. 전체 지표에서도 저장한 수식을 검색·추가합니다.

기존 차트의 수식 지표는 처음 한 번 목록으로 복사하며 차트는 그대로 유지합니다. 목록은 서버의 .runtime/custom-studies.json에 따로 저장돼 PC·휴대폰에서 공유됩니다. 목록을 수정해도 차트에 이미 추가한 복사본은 유지됩니다. 차트의 수식 설정에는 **내 지표에 저장**이 있어 수정한 선을 새 정의로 보관할 수 있습니다. 차트에서 제거해도 목록은 남고, 목록에서 삭제해도 차트의 선은 남습니다. 삭제 전에 이를 안내합니다. 지표 창을 열면 목록을 다시 조회하고 **서버 설정 불러오기**로 직접 갱신할 수 있습니다. 다른 기기의 새 저장을 오래된 화면이 덮어쓰지 못하도록 검사합니다.

## NW 차이값의 중앙 90% 범위

**백분위수(데이터, 조회 봉 수, 백분위)**는 관측값을 정렬하고 (N−1)×백분위/100 위치를 선형 보간합니다. 조회 봉 수 1~500 정수·백분위 0~100이며 함수 전체 뒤 [1]은 직전 완성봉부터 조회합니다. 준비 봉이나 입력값이 빠지면 미확인값입니다. 시각·현재 포지션 값으로 존재하지 않는 과거 분포를 만들지 않습니다.

사용자 지표 예제에서 **NW 차이값 중앙 90% · 상단/하단 (완성 100봉)**을 선택합니다. 각 봉의 하이킨종가 − 그때 NW를 구하고, 직전 완성 100봉의 95·5백분위수를 현재 NW에 각각 **더합니다**. 하단도 더하기이며 차이값 자체에 음수가 포함됩니다. 상·하단은 비대칭일 수 있고 NW가 두 선의 정확한 가운데일 필요는 없습니다. 현재 양봉이 기준 분포를 넓히지 않도록 백분위수 함수 뒤에만 [1]을 붙였습니다. 현재 NW는 진행봉에 따라 움직입니다.

상단: **NW(하이킨종가, 100, 8) + 백분위수(하이킨종가 - NW(하이킨종가, 100, 8), 100, 95)[1]**

하단: **NW(하이킨종가, 100, 8) + 백분위수(하이킨종가 - NW(하이킨종가, 100, 8), 100, 5)[1]**

최초 계산에는 200봉이 필요합니다. ‘중앙 약 90%’는 과거 **차이값 분포**의 범위이며, 최근 실제 가격 100개를 현재 밴드가 90% 포함한다거나 미래 가격이 90% 들어올 확률을 뜻하지 않습니다. 과거점은 각 시점에 알려진 데이터로 계산하고 나중 봉으로 다시 맞추지 않습니다. 일반 MA의 차이값이나 다른 봉 데이터에도 함수를 사용할 수 있습니다. 계산량 제한을 적용하며 추가 바이낸스 조회를 만들지 않습니다.

계산 참고: [선형 표본 분위수](https://numpy.org/doc/stable/reference/generated/numpy.quantile.html). 수학 정의를 자체 구현했으며 외부 코드를 포함하지 않습니다.

## NW 사용자 수식

홈 → 지표 → ＋ 새 수식 지표 → 가격 차트 위에서 **NW(하이킨종가, 100, 8) + ATR(14) * 1.5**를 입력합니다. 목록에 저장한 뒤 내 지표에서 ＋를 눌러 차트에 추가합니다. 예제 수식에도 상단선·하단선·중심선을 제공합니다. 하단선은 더하기를 빼기로 바꿉니다. 100은 현재 포함 계산 봉 수, 8은 Bandwidth, 14는 일반 봉 ATR 기간, 1.5는 ATR 폭 배수입니다. 1.5를 키우면 중심선에서 더 멀어지고 8을 키우면 더 부드러워지며 반응이 늦어집니다. 이 수치는 비교용 예시이며 특정 반등을 걸러내는 최적값이 아닙니다.

**NW(데이터, 계산 봉 수, Bandwidth)**는 기본 NW 지표의 Gaussian 중심선과 같은 계산입니다. 계산 봉 수 2~500 정수·Bandwidth 0.1~300이며 일반·하이킨 가격 및 데이터 조합을 지원합니다. 미래 봉으로 과거값을 다시 맞추지 않으며, 진행봉은 변합니다. 기본 NW 상·하단의 평균 절대오차 방식과 사용자 식의 ATR 폭은 다릅니다.

봇 조건식에서도 사용하며 함수 전체에 @봉주기를 붙입니다. 예: **상향돌파(하이킨종가, NW(하이킨종가, 100, 8) + ATR(14) * 1.5)@1m[1]**. 다중종목은 A.하이킨종가처럼 소스를 지정합니다. 이 예시는 조건식만 제공하며 기존 봇에 자동으로 적용하지 않습니다. 준비 봉·입력 데이터가 부족하면 미확인값이며 현재 시간·현재 포지션의 과거 이력을 생성하지 않습니다. 계산량 제한을 적용합니다.

## NW 인벨로프와 기울기

홈 → **지표**에서 **NW 지표 추가**와 **NW_SLOPE 지표 추가**를 선택합니다. 기존 지표를 그대로 두고 가격 위에는 NW 중심선·상단·하단, 별도 패널에는 기울기를 표시합니다. 중심선만 보려면 스타일에서 상단·하단과 배경 채우기를 끕니다.

Gaussian 또는 Rational Quadratic 커널, 계산 봉 수(현재 포함, 기본 100), Bandwidth(기본 8), RQ 상대 가중치(기본 1), 가격 소스와 일반/하이킨아시 기준을 설정합니다. 가중치는 Gaussian에서 exp(−(봉 거리/Bandwidth)²/2), RQ에서 (1+(봉 거리/Bandwidth)²/(2α))^(−α)입니다. 계산 창 전체가 있을 때부터 커널 가중평균을 표시합니다. 상·하단은 중심선 ± 관측된 절대오차의 이동평균(기본 20봉) × 배수(기본 3)입니다. 오차는 각 봉 당시에 계산한 추정값을 사용하며 과거 구간 전체를 다시 맞추지 않습니다. 따라서 다른 제작자의 조회 길이·오차 기간·초기화·재도색 설정과 값이 다를 수 있습니다.

기울기는 (현재 NW − N봉 전 NW) ÷ |N봉 전 NW| × 100 ÷ N으로, 기본 N=3의 **봉당 변화율(%/봉)**입니다. 화면상의 각도나 수익률이 아닙니다. ±0.01 %/봉 안은 중립색, 그 위는 상승색, 아래는 하락색입니다. 기준과 색상은 수정할 수 있으며 중심선 색상에도 같은 판정을 적용합니다. 두 지표의 커널·계산 봉 수·Bandwidth·RQ 가중치·소스·캔들 기준을 맞추면 같은 중심선을 기준으로 비교합니다. 밴드 폭 배수는 기울기에 영향을 주지 않습니다.

미래 봉을 사용하지 않는 비재도색 방식만 제공합니다. 진행 중인 봉의 값은 변하고, 원본 가격 데이터·설정이 바뀌면 결과도 달라질 수 있습니다. 준비 봉 부족·누락 데이터·0 나눗셈은 비워 두고 연결하지 않습니다. 기존 차트 설정과 같이 서버에 저장되며 추가 바이낸스 요청을 만들지 않습니다. 기본 NW 지표와 별도로 사용자 지표·봇 조건식에서 NW() 가우시안 중심선을 사용할 수 있습니다. 기존 봇 조건식·주문 설정은 자동으로 변경하지 않습니다. 이 지표만으로 반등과 전환을 확정하거나 수익성을 보장하지 않습니다.

계산 참고: [NW 커널 회귀](https://www.tradingview.com/script/AWNvbPRM-Nadaraya-Watson-Rational-Quadratic-Kernel-Non-Repainting/), [NW 인벨로프 구조](https://www.luxalgo.com/library/indicator/nadaraya-watson-envelope/). 설명된 수학 구조를 자체 구현했으며 외부 Pine 스크립트 코드를 포함하지 않습니다.

## 보조지표

홈 차트의 **지표**에서 DMI(+DI·-DI·ADX), ADX 단독, CCI, MFI, 볼린저 밴드폭(BBW), 볼린저 %B를 추가합니다. 기존 SMA·EMA·볼린저밴드·RSI·MACD·스토캐스틱·ATR·VWAP·거래량·수식 지표도 함께 사용할 수 있습니다.

각 지표는 기간·캔들 계산 기준(차트와 같게/일반/하이킨아시)·색상·선 굵기·표시 봉주기를 설정합니다. 표시 설정은 서버에 저장해 PC·같은 Wi-Fi·휴대폰에서 공유하며, 지표 선을 클릭하면 해당 봉의 값을 툴팁에서 확인합니다. 자동매매 조건 설정과는 별도입니다.

DMI의 DI 기간과 ADX 평활 기간은 별도로 지정하며 와일더 RMA를 사용합니다. %B는 하단=0·중심=0.5·상단=1이며 밴드 밖의 값도 유지합니다. BBW는 (상단−하단)/중심선×100입니다. 비교할 볼린저밴드와 기간·배수·가격 소스·캔들 기준을 맞춰 주세요. MFI는 구간 내 양·음의 자금 흐름이 모두 없으면 값을 비워 두며, 준비 봉이 부족한 지표도 임의의 값을 만들지 않습니다.

계산 정의: [DMI](https://www.tradingview.com/support/solutions/43000502250-directional-movement-dmi/), [CCI](https://www.tradingview.com/support/solutions/43000502001-commodity-channel-index-cci/), [MFI](https://www.tradingview.com/support/solutions/43000502348-money-flow-mfi/), [BBW](https://www.tradingview.com/support/solutions/43000501972-bollinger-bandwidth-bbw/), [%B](https://www.tradingview.com/support/solutions/43000501971-bollinger-bands-b-b/).

## 잔액 비율로 운용예산 지정

봇 기본 설정의 **예산 지정 방식**에서 고정 USDT 금액, 전체 선물 USDT 지갑 금액의 비율, 현재 주문 가능 금액의 비율을 선택합니다. 단일·다중종목 봇에 모두 적용됩니다.

주문 가능 잔액 비율은 매 주문 준비 때 최신 계좌 잔액으로 계산합니다. 이 봇이 이미 사용·예약한 증거금을 기준 잔액에 되돌려 더해 자기 체결 때문에 한도가 이중 차감되지 않게 하며, 계산 기준은 전체 USDT 지갑 잔고를 넘지 않습니다. 다른 봇·수동 거래의 사용 증거금은 되돌려 더하지 않습니다. 포지션이 없을 때 주문 가능 100 USDT에서 50%는 50 USDT, 다음 매매 때 80 USDT면 40 USDT입니다.

보유 포지션을 자동 리밸런싱하지 않고 새 진입 한도에 적용합니다. 비율 예산은 봇 실현손익을 중복 가산하지 않으며 금액 기준 손익 운용·이익 재투자 비율은 사용하지 않습니다. 주문 가능 잔액이 0이거나 최소 주문금액보다 작으면 감시를 유지하며 진입을 기다립니다. 다른 봇의 배정 예산과 겹치면 기존 전체 배정 검사·자동 축소 정책을 따릅니다.

## 삭제한 봇의 개별 통계

매매 기록·통계 창의 봇 선택에서 **삭제된 봇**을 따로 선택할 수 있습니다. 앞으로 삭제하는 봇은 이름·삭제 시점 기준예산·통계 초기화 정보·다중 종목 구성원 식별자를 로컬 원장에 보존하며 운용예산에는 포함하지 않습니다. 체결·수수료·펀딩·최대 손익 관측 기록을 삭제하지 않습니다.

이미 삭제된 봇도 남은 체결 기록으로 개별 통계와 거래별 수익률·누적 순손익 그래프를 조회합니다. 예전 이름을 복원할 수 없으면 종목명과 식별자로 표시합니다. 삭제 전 기준예산이 남지 않은 경우 누적 예산 대비 수익률·기준예산 환산 잔액은 미확인으로 표시하며, 거래별 증거금 대비 수익률은 확인 가능한 기록으로 계산합니다.

## 과거 체결의 수수료 확인

봇의 담당 종목을 변경해도 과거 주문은 원래 종목으로 조회합니다. 공유 체결 수량의 미세한 소수점 차이가 수수료 미확인으로 남지 않도록 처리하며, 이미 저장된 배정 체결·수수료가 모두 일치하는 경우 확인 표시만 복구합니다. 매매 손익·체결·수수료를 중복 반영하지 않습니다. 실제 수수료가 누락돼 예산 손익 기준 재설정을 보류할 때는 해당 종목과 주문 번호를 표시합니다.

## 미체결 주문 기한

미체결 대기 시간이 지나면 다른 조회·봇 처리 사이에서도 해당 주문을 우선 확인합니다. REST 시세 조회 주기가 길어도 주문 기한은 약 1초 간격으로 확인하며, 정지·청산 조건을 확인한 뒤 기존 주문의 취소와 실제 잔량 대조를 거쳐 설정된 후속 처리를 실행합니다. 통계·수수료 내역보다 주문·취소·포지션 검증 요청을 먼저 전송합니다.

기한은 체결 완료를 보장하는 시간이 아닙니다. 이미 진행 중인 요청·거래소 응답·취소 확인·호출 제한으로 추가 시간이 걸릴 수 있습니다. 기한 발견·취소 요청/확인·주문 접수 시각과 최근 API 큐 대기/처리 시간을 남깁니다. 접수 여부가 불명확한 주문은 재전송하지 않습니다.

## 지표 설정 저장

지표 목록·기간·수식·색상·볼린저 배경은 서버의 .runtime/chart-settings.json에 저장합니다. 127.0.0.1·localhost·같은 Wi-Fi 주소에서 같은 설정을 불러옵니다. 처음 실행한 기존 주소의 브라우저 지표를 서버로 옮기므로, 처음 업데이트한 뒤에는 원래 사용하던 주소로 한 번 열어 주세요. 기존 브라우저 값도 보관하며 지표 창의 **이 기기 이전 설정 복원**으로 되돌릴 수 있습니다.

동시에 연 다른 화면에서 저장하면 오래된 설정의 덮어쓰기를 막습니다. 지표 창의 **서버 설정 불러오기**를 눌러 최신값을 확인하세요. 아직 저장하지 않은 기본 지표로 기존 서버 설정을 덮어쓰지 않습니다. 지표의 직전 서버 백업도 보관합니다. 차트 종목·확대 범위는 기존처럼 브라우저에 저장합니다.

## 차트 유형

차트 상단 유형 메뉴에서 **캔들·바·하이킨아시·라인·마커 라인·스텝 라인·영역·베이스라인**을 고를 수 있습니다. 라인·영역은 실제 종가를, 하이킨아시는 합성 가격을 표시합니다. 베이스라인의 기준선은 화면에 보이는 종가 범위의 중간값이며 이동·확대 시 갱신됩니다.

유형을 바꿔도 지표·현재가·계좌 평단·수평선·체결 B/S와 표시 범위는 유지됩니다. 봇 조건식의 계산 기준은 바뀌지 않으며 홈의 선택 유형은 브라우저에 저장합니다.

## 차트 체결·봉주기

차트의 **체결 B/S**를 켜면 앱에 기록된 실제 매수를 B, 매도를 S로 표시합니다. 실제 캔들 몸통·꼬리나 가격선·보조지표를 클릭·터치하면 차트 안 툴팁에서 가격·보조지표 값과 롱·숏 진입/정리, 한국시간 체결 시각·수량·가격을 볼 수 있습니다. 다른 봉을 누르면 내용이 바뀌며, 닫기·바깥 클릭·Escape로 닫습니다. 숏 정리는 매수(B)입니다. 미체결 주문이나 포지션을 가져온 시점을 체결로 표시하지 않습니다. 거래소 체결시각이 없는 과거 기록은 **기록시각**으로 구분합니다. 이 조회로 바이낸스 API를 추가 호출하지 않습니다.

자주 쓰는 봉주기 옆 **⋯**에서 30분을 포함한 15개 주기를 선택할 수 있습니다. 선택 주기·차트 설정은 브라우저에 저장하며, 체결내역의 종목을 누르면 홈 차트가 해당 종목으로 바뀝니다.

체결내역은 **롱 진입 / 숏 진입 / 롱 정리 / 숏 정리**로 구분하고 매수·매도도 작게 함께 표시합니다. BUY는 롱 진입 또는 숏 정리일 수 있습니다.

볼린저밴드 설정의 **스타일 → 배경 채우기**에서 상·하단 사이 배경색과 투명도를 정합니다. 투명도 **0%는 진하게, 100%는 완전히 투명하게** 표시합니다. 빈 차트 배경을 눌러서는 툴팁이 열리지 않습니다.

왼쪽 메뉴(모바일은 하단바)에는 현재 한국시간이 초 단위로 표시됩니다.

## 차트 진입 평단

홈 차트에는 조회 중인 USDT 선물 종목의 **계좌 진입 평단**이 점선과 가격축 라벨로 표시됩니다. 롱은 초록색, 숏은 빨간색이며 추매·부분 정리·전량 정리 시 갱신됩니다. 일반 캔들·하이킨아시·확대 차트에서 같은 실제 진입 가격을 사용하고, 같은 종목을 여러 봇이 운용해도 계좌의 통합 평단을 표시합니다. 헤지 모드에서는 롱·숏을 각각 표시합니다.

## 운용·보관

공유 맵 대신 각 봇이 자기 책상에서 트레이딩하는 캐릭터와 함께 목록에 표시됩니다. 캐릭터·이름 또는 설정 버튼을 누르면 봇 설정을 열고, 각 행에서 시작·정지와 더보기 기능을 사용합니다.

봇 목록의 **운용 / 보관** 탭에서 구분하고 각 봇의 **⋯ → 운용으로 이동 / 보관으로 이동**으로 변경합니다. 모달에서는 **운용예산에 포함** 체크로 선택합니다. 새 봇·복사본은 기본 보관이며 보관한 설정은 예산 합계에서 제외됩니다. 운용으로 이동한 뒤 **시작**을 눌러야 매매합니다.

이동·체크 시 남은 배정 한도를 바로 안내합니다. 보유 포지션·미해결 주문이 있으면 보관할 수 없습니다. 기존 봇은 운용 상태를 유지합니다.

## 예산 지정과 부족 시 처리

봇 기본 설정에서 **금액 · USDT** 또는 **전체 선물 USDT 지갑 금액의 비율 · %**를 선택합니다. 비율은 미실현손익을 제외한 최신 전체 선물 USDT 지갑 금액으로 주문 준비 시 계산하며, 지갑 잔고에 반영된 손익을 다시 더하지 않습니다.

**예산 부족 시 → 부족하면 가용 한도까지 자동 축소**를 선택하면 목표 100 USDT에 가용 한도가 70일 때 70까지 운용하고, 잔고 회복 시 목표까지 복구합니다. 기존 방식은 그대로 선택할 수 있습니다. 여러 자동 축소 봇은 보유·예약 증거금을 우선 반영하고 남은 한도를 목표 예산에 비례해 나눕니다. 한도가 줄어도 보유 포지션을 강제 정리하지 않으며, 실제 주문은 거래소 주문 가능 금액과 최소 주문·수수료 여유 한도를 따릅니다.

**손익에 따른 예산 운용 → 최소 한도 유지 + 손익 반영**은 기준 예산 + 누적 확정손익을 계산하되 입력한 최소 USDT 금액 아래로 한도를 낮추지 않습니다. 과거 손실을 없애지는 않습니다. 기준 100·최소 30에서 누적 손실 100이면 한도 30, 이후 20 이익이어도 30, 추가 20 이익이면 40입니다(이익 반영 100%). 이익 중 예산에 더할 비율도 적용됩니다. 실제 주문 가능 금액은 지갑의 가용 금액을 넘지 않으며, 예산 부족 시 자동 축소를 함께 선택하면 실제 한도는 최소치보다 작아질 수 있습니다.

## 청산 체결·취소 확인 대기

거래소 TP/SL이 실행 중이거나 기존 주문의 취소가 확인 중이면 봇을 오류 정지시키지 않고 **정리 확인 중**으로 표시합니다. 확인이 끝날 때까지 추가 청산·진입은 보류하고, 남은 보유 수량이 확인되면 그 수량만 정리합니다. 대기 의도와 전송한 청산 주문을 저장해 재시작 중에도 중복 전송하지 않습니다. 사용자가 정지한 상태는 유지하며, 실제 주문 접수 여부 불명·영구 거절은 계속 구분합니다.

## 홈 미체결 주문 취소

홈 **미체결 → 잔량 취소**에서 봇·앱 수동·바이낸스 직접 일반 주문을 선택해 취소합니다. 일부 체결된 수량은 유지하며 주문 허용이 꺼져 있어도 취소할 수 있습니다. 봇 주문의 잔량 시장가 전환은 중단하지만 봇 자체를 정지하지는 않습니다. 봇이 켜져 있고 다음 실행 조건이 충족되면 새 주문은 나올 수 있습니다. 봇 TP/SL은 자동 관리되므로 **보호 설정**에서 변경합니다.

## 예산 손익 기준과 이익 반영 비율

봇 **⋯ → 예산 손익 기준 재설정**에서 매매 기록·통계를 유지한 채 현재까지의 확정손익을 예산 계산에서 제외합니다. 적용 전 현재 한도와 재설정 후 한도를 확인합니다. 보유 중에도 가능하지만 미체결 진입·접수 미확인 주문·수수료 대조가 남으면 먼저 확인해야 합니다. 한도가 늘어나면 지갑 잔고와 다른 봇의 배정액을 다시 검사합니다. 보유 포지션은 정리 시 확정되는 손익부터 새 기준에 반영합니다.

기본 설정의 **이익 중 예산에 더할 비율**은 0~100%로 정합니다. 예산 200 USDT, 이익 반영 50%에서 매매이익 100이 확정되면 한도는 250, 이후 40 손실이면 210이 됩니다. 손실·확인된 USDT 수수료는 전액 차감하며 미실현손익·펀딩은 예산 계산에서 제외합니다. 비율 변경은 저장 후 새로 확정되는 매매이익부터 적용하고, 이전 반영액은 바꾸지 않습니다. 기존 설정은 100%를 유지합니다.

손익 반영은 늘어난 한도로 계속 운용하고, 원금 한도 유지는 설정한 원금을 상한으로 둡니다. 고정 한도는 손익에 따라 한도가 바뀌지 않습니다. 이 설정은 주문 한도 계산이며 실제 자금을 이체하거나 별도 지갑에 분리하지 않습니다. 단일·다중종목 봇 모두 지원하며 계좌가 바뀌면 예산 손익 기준도 새로 시작합니다.

### 손실 이월과 이익 복구 설정

봇 설정 → 기본 설정 → 운용 예산에서 **계산 예산의 음수 처리**와 **손실 복구 중 이익 반영**을 각각 선택합니다. 단일·다중종목 봇 모두 지원하며 기존 봇의 기본값은 음수 손실 계속 누적·복구에도 설정 비율 적용입니다.

- **음수 손실 계속 누적**: 계산 예산이 0 아래여도 손실을 유지하고 이후 반영 이익과 상계합니다. **0에서 멈춤**: 계산 예산을 0 아래로 내리지 않고 초과 손실은 예산 계산에서 이월하지 않습니다. 실제 매매 손실·기록·통계는 유지합니다. 최소 운용한도 설정은 실제 운용한도의 하한이며 계산 예산의 0 하한과 별개입니다.
- **손실 복구에도 설정 비율 적용**: 각 매매이익의 설정 비율만 예산에 더합니다. **복구분 100%**: 손실로 줄어든 계산 예산을 먼저 전액 복구하고, 복구를 넘는 이익에만 설정 비율을 적용합니다. 예: 기준 200·이익 반영 50%에서 이익 100 → 예산 250, 손실 40 → 210, 이후 이익 60 → 손실 복구 40 + 남은 이익 20의 50%인 10을 반영해 260입니다(수수료 생략). 손실과 USDT 수수료는 전액 차감하며 펀딩·미실현손익은 봇 예산 계산에 포함하지 않습니다.

설정 변경은 새로 확정되는 손익부터 적용하고 과거 이익 반영분을 재계산하지 않습니다. 0에서 멈춤을 선택하면 기존 음수 계산 예산도 저장 시 0으로 맞춥니다. 복구 대상은 처음 적용 시 현재 기준예산 대비 부족분에서 시작하며 이후 늘어난 계산 예산에서 발생한 손실도 추적합니다. 잔액 비율 예산은 최신 계좌 잔액으로 직접 계산하므로 이 두 선택을 따로 적용하지 않습니다. 예산 손익 기준 재설정 시 복구 대상 손실도 초기화하고 매매 기록·통계는 유지합니다.

## 다중종목 봇

봇 탭의 **+ 다중종목 봇**에서 2~8종목과 증거금 예산 비중(합계 100% 이하, 남은 비중은 미사용)을 정합니다. 조건마다 종목별 롱·숏 진입, 부분·전량 정리와 레버리지를 지정합니다. 예: `(A.종가 > SMA(B.종가, 20))@1h[1]`. A·B는 설정한 종목 별칭이며, `BTCUSDT.종가`처럼 심볼로 직접 참조할 수도 있습니다.

여러 주문은 각각 체결됩니다. 일부 실패 시 신규 진입을 중지하고 이미 체결된 보유분의 관리를 계속합니다.

## 요일·시간 조건

기존 조건식에 `요일() <= 금요일 AND 시간범위(900, 1800)`을 AND로 조합하면 한국시간 월~금 09:00 이상 18:00 미만에만 해당 행동을 실행합니다. `시각() >= 1800`처럼 비교해 정리·정지 행동에도 사용할 수 있습니다. 월요일=1 ~ 일요일=7입니다.

`시간범위(2300, 600)`은 자정을 넘고, `시간범위(0, 2400)`은 하루 전체입니다. 자정 이후 요일은 다음 날짜를 따릅니다. `요일(미국동부)`·`시간범위(930, 1600, 미국동부)`·`시각(UTC)`로 시간대를 지정할 수 있습니다. 기본은 한국시간이며 미국 동부시간은 서머타임을 자동 반영합니다.

요일·시간은 봉 시각이 아닌 현재 감시 시각입니다. 전체 수식의 `@1h[1]`로 과거 시각으로 이동하지 않습니다. 재실행 빈도는 기존 재실행 설정을 따르며, 공휴일·거래소 휴장일·조기 폐장은 자동으로 구분하지 않습니다. 기존 봇 수식에는 자동으로 시간 제한을 추가하지 않습니다.

## 같은 Wi-Fi에서 접속

서버 PC의 **설정 → 같은 Wi-Fi 접속 허용**을 켜면 휴대폰·다른 PC에서 열 주소와 6자리 코드가 표시됩니다. 같은 공유기에 연결한 기기에서 주소를 열고 코드를 입력하세요. 허용 설정은 재시작 후에도 유지되며, 끄면 다른 기기 접속만 해제됩니다. API 키 관리는 서버 PC에서 합니다.

## REST 요청 내역

**설정 → 데이터 수신 → REST 요청 내역**에서 직전 1분의 요청 종류별 횟수·가중치를 봅니다. 집계는 서버 재시작 이후 앱에서 보낸 USDT 선물 요청만 포함하며 IP 전체 사용량과 다를 수 있습니다. 자체 조회량 조절과 실제 거래소 제한을 구분합니다.

웹소켓 연결 중 체결·수량 차이가 없으면 최근 계좌 조회를 재사용하고, 보유·주문·감시가 없는 종목은 대조 간격을 늘립니다. 앱의 자체 조회량 대기는 해당 작업에만 적용합니다. 실제 거래소가 제한한 경우에는 해제 시각을 따릅니다.

## 메이커 전용 주문 재시도

Post-only 지정가가 메이커 조건 때문에 확실히 거절되면 봇을 정지하지 않고 **메이커 주문 대기**로 표시합니다. 조건이 계속 충족될 때 5→10→20→30초 간격으로 최신 호가와 예산을 다시 확인합니다. 정리 재시도를 기다리는 종목은 새 진입을 보류합니다. 주문이 접수된 뒤의 잔량 취소·시장가 전환은 설정한 정책을 따릅니다. 접수 여부가 불확실한 주문은 재전송하지 않고 조회합니다.

## 현재 포지션 수익률

봇 목록에서 **평가**와 **비용 후 예상**을 나란히 봅니다. 둘 다 현재 보유 증거금 대비이며, 비용 후 예상은 남은 보유분의 진입 수수료·발생 펀딩·현재 평가가격 기준 시장가 정리 예상 수수료를 반영합니다. 실제 체결가격·주문방식·할인에 따라 달라지며 미래 펀딩은 제외합니다. 부분 정리한 수량의 손익·비용은 남은 포지션에 섞지 않습니다. 비용을 확인할 수 없는 인수 포지션 등은 미확인으로 표시합니다.

## 차트 가격·시간과 평가자산

차트의 시간축과 십자선은 한국시간(KST)입니다. 캔들을 클릭·터치하면 해당 봉의 시가·고가·저가·종가·거래량과 지표 값을 고정하고, **선택 해제**로 최신 봉으로 돌아갑니다. 하이킨아시는 합성 OHLC와 실제 종가를 구분합니다. 우측 **현재가** 라벨은 캔들 방식과 무관하게 실제 최종체결 가격이며 진입 평단선·사용자 수평선과 별도로 관리됩니다.

봇 탭의 **USDT 평가자산**은 계좌 전체의 선물지갑 잔고 + 현재 미실현손익입니다. 봇 외부 수동 포지션도 포함하며 지갑 잔고·미실현손익을 함께 표시합니다. 아직 발생하지 않은 정리 수수료·향후 펀딩은 포함하지 않으며 주문 가능 잔액·봇 운용한도와 다른 표시용 금액입니다. 봇 목록에는 현재 보유분의 평가손익·비용 후 예상손익을 %와 USDT로 함께 표시합니다.

## 매매 기록·통계

**활동 기록 → 매매 기록·통계** 또는 봇 **상태·기록 → 매매 기록·그래프**에서 확인합니다. 진입부터 전량 정리까지 묶은 거래별 수수료·펀딩 포함 손익과 수익률, 누적 수익률·금액 추이, 승률·평균 수익률·확정손익 기준 낙폭을 봅니다. 비용이 미확인인 기록은 구분합니다.

거래별 **보유 중 최대이익·최대손실**을 USDT·%와 금액 최대 시각으로 기록하고, 완료 거래들의 최고·평균도 집계합니다. 기존 마크가격 자료를 사용하며 추가 API 조회는 없습니다. 실제 체결가도 반영하며 계산은 부분 정리 실현손익 + 남은 평가손익입니다. 수수료·펀딩 차감 전입니다. %는 각 관측 시점까지의 누적 진입 증거금 대비여서 금액 최대 시점과 % 최대 시점은 다를 수 있습니다.

과거 완료 거래는 **미수집**입니다. 기능 적용 당시 보유 중이거나 수동으로 인수한 포지션은 **부분 관측**으로 표시하고 최고·평균 통계에서 제외합니다. 관측 공백·늦게 확인된 체결도 구분하며, 연결 중단이나 관측 사이의 실제 최고·최저 가격을 추정하지 않습니다. 기록은 서버 재시작 후에도 보존됩니다.

## 조건식에서 현재 수익률 사용

`현재수익률() >= 10 OR 현재수익률() <= -5`를 입력하고 정리 행동을 선택하면 +10% 익절 또는 -5% 손절 조건으로 사용합니다. 볼린저·요일·시간 조건과 AND/OR로 조합할 수 있습니다.

`현재수익률()`은 마크가격의 평균 진입가 대비 변화에 실제 보유 배수를 반영한 진입 증거금 기준 %로, TP·SL의 진입 증거금 기준과 같습니다. `가격변동률()`은 배수 미반영 %, `현재손익()`은 현재 보유분의 미실현손익 USDT입니다. 수수료·펀딩·예상 정리 수수료는 제외합니다. 추가 진입하면 현재 평균 진입가를 사용합니다.

다중종목 봇의 `현재수익률()`은 합산 미실현손익 ÷ 합산 진입 증거금 × 100이며, `A.현재수익률`·`B.현재손익`처럼 종목별 값도 사용할 수 있습니다. 포지션이 없을 때 수익률·손익은 미확인값이고, `포지션보유() = 0`으로 미보유 상태를 확인합니다. 현재 보유 정보이므로 `@1h[1]`로 과거 손익이 되지 않습니다. 기존 `수익률`의 봉 종가 기반 호환 계산은 유지합니다.

## 데이터 수신

**설정 → 데이터 수신**에서 웹소켓(기본) 또는 REST를 선택합니다. REST 조회 간격은 3~300초로 저장되며, 웹소켓이 끊겼을 때의 보완 조회에도 적용됩니다. USDT 선물·현물·COIN-M 시세는 웹소켓 연결을 공유합니다. 계좌 변경 이벤트 뒤 상세 내역을 확인하며 60초마다 대조합니다. 최초 봉 로딩·재연결 복구·주문 전 검증은 REST를 사용하고, 옵션 조회도 REST입니다.

## 주문 금액이 부족할 때

운용 중 새 주문에 쓸 증거금이 없거나 주문 금액·수량이 거래소 최소 기준보다 작으면 **진입 대기**로 표시하고 그 주문을 보내지 않습니다. 조건 감시와 보유 포지션의 정리·TP·SL 관리는 계속합니다. 같은 조건이 여전히 맞고 주문 가능한 금액이 생기면 다시 확인하며, 반복 강제 조회에는 간격을 둡니다. 최대 주문 수량 초과·실제 거래소 주문 거절·소유 포지션 불일치 등은 별도의 확인 필요 상태로 남습니다.

## 업데이트

설정의 **업데이트 확인**, **npm run update:check**, **update.cmd** 모두 Git 설치 없이 사용할 수 있습니다. 프로그램을 종료하고 **update.cmd**를 실행하면 공식 릴리즈 ZIP과 체크섬을 내려받아 검증한 뒤 적용합니다. 실패하면 기존 파일을 복구하며, 키·봇 설정·매매 기록·차트·즐겨찾기는 보존합니다. 완료 후 **run.cmd**로 다시 시작하세요.

구버전 update.cmd에서 Git 설치를 요구한다면 v0.4.72 이상 Windows ZIP을 한 번 내려받아, 프로그램을 종료한 상태로 기존 폴더에 덮어쓰세요. **.runtime 폴더는 지우지 마세요.** 이후에는 update.cmd만 실행하면 됩니다. 직접 소스를 수정했다면 덮어쓰지 않고 중단합니다. 개발자가 Git 기반 main 브랜치 업데이트를 원할 때만 `node tools/update.mjs --source`를 사용합니다.

과거 버전에서 `tests/app-update.test.mjs`의 `package.json ENOENT`로 업데이트 검증이 중단됐다면, 프로그램 실행 창을 종료하고 **기존 폴더의 update.cmd를 다시 실행**하세요. 0.4.30에서 해당 검증 오류를 수정했습니다. 키·설정·기록은 기존 `.runtime`에 유지됩니다.

- **설정 초기화**: 이름·종목·비중·예산·외형을 유지하고 조건·주문·운용·보호를 기본값으로 되돌립니다. 진입 조건은 `FALSE`로 시작합니다. 편집 후 **설정 저장**을 눌러야 적용됩니다.
- **기록·통계 초기화**: 현재 시점을 새 집계 시작점으로 기록합니다. 이후 기록·손익·수수료·펀딩·통계·그래프만 표시하며, 주문·체결 원장은 삭제하지 않습니다. 손실을 포함한 실제 운용한도는 초기화하지 않습니다.

초기화는 봇 정지 후 보유 포지션과 미체결 주문이 없을 때만 사용합니다. 기록·통계 초기화는 계좌 연결 상태에서 거래소 보유·주문도 다시 확인하며 수량 불일치를 해제하는 용도로 사용할 수 없습니다.

### 공유 계좌와 정리 대상

같은 종목을 여러 봇과 수동 주문이 함께 매매할 수 있습니다. 신규 진입은 각 봇의 남은 운용예산과 계좌 주문 가능 금액 안에서 제한됩니다. 거래소 포지션은 합쳐지지만, 봇이 진입한 배정 수량과 수동 보유분은 별도로 기록합니다.

각 단일 조건·다중종목 대상의 **정리 대상**을 고를 수 있습니다.

- **이 봇 보유분**: 이 봇에 배정된 수량에 정리 비율을 적용합니다. 기존 조건의 기본값입니다.
- **계좌 전체 보유분**: 다른 봇과 수동 보유분을 포함한 계좌 수량에 비율을 적용합니다. 롱·숏 정리는 해당 방향 기준입니다. 현재수익률 등 포지션 조건도 선택한 대상 기준으로 평가합니다.

바이낸스에서 직접 부분·전량 정리한 체결은 수수료와 함께 자동 반영합니다. 특정 봇을 지정하지 않은 정리는 그 시점의 봇·수동 보유 수량 비율로 배분하며 거래소 수량 단위에 맞춥니다. 외부 추가 진입은 수동 보유분으로 기록하고, 필요하면 **수동 포지션 가져오기**로 기존 봇에 배정할 수 있습니다. 새 봇·복사본은 처음 **시작**하기 전에는 계좌 정리 조건도 실행하지 않습니다. **정지**는 자동 진입·정리·TP/SL 관리를 모두 중지합니다. 보유 포지션은 유지하고, 이 봇의 미체결 주문과 보호 주문은 취소합니다. 이미 체결 중인 주문은 결과가 확정될 때까지 정지·취소 확인 중으로 표시합니다. 다시 시작해야 자동 매매가 재개됩니다. 설정 저장도 같은 정지 동작을 수행합니다. 정지된 봇을 임의로 다시 시작하지 않습니다.

같은 종목의 레버리지·증거금 모드는 계좌 공통 설정을 따릅니다. 보유 중에는 실제 계좌 배수를 사용하며, 단방향 계좌에서 반대 매매는 기존 포지션과 상계됩니다. 봇별 손익은 귀속 체결·진입가 기준으로 계산한 전략별 손익입니다. 일부 보유분만 정리할 때 바이낸스 계좌에 표시되는 실현손익과 시점별 배분이 다를 수 있으며, 홈 포지션 표는 거래소 계좌 값을 표시합니다.

계좌 웹소켓 이벤트와 저장된 체결 번호를 사용하고, 새 체결의 가격·수수료는 REST로 대조합니다. 재시작·일시적인 호출 제한·저장 복구 후에도 이미 반영한 체결을 재주문하거나 중복 집계하지 않습니다. 새 체결이 아직 도착하지 않았으면 대조가 끝날 때까지 해당 종목의 신규 주문을 보류합니다.

## 다른 봇 배정 후 남은 예산의 비율

단일봇과 다중종목 봇의 기본 설정 → 예산 지정 방식에서 선택합니다. 금액·전체 지갑 비율·현재 주문 가능 금액 비율은 그대로 유지됩니다.

전체 선물 USDT 지갑 금액에서 기존 방식으로 운용에 포함된 봇들의 현재 배정액을 먼저 뺍니다. 새 방식을 선택한 봇들은 그 공통 잔여 예산에 각자의 비율을 곱합니다. 지갑 1,000 USDT, 기존 방식 배정 400 USDT라면 공통 잔여는 600 USDT입니다. A·B 각각 5%는 각각 30 USDT이며 서로의 30을 다시 빼지 않습니다.

이 방식으로 운용에 포함한 봇의 비율 합계는 100% 이하여야 합니다. 정지한 운용 봇도 배정에 포함하고 보관한 봇은 제외합니다. 다중종목 봇은 부모의 비율을 한 번만 계산하고 종목별 비중으로 나눕니다. 지갑·다른 방식 배정액이 변하면 새 진입 한도를 다시 계산하며 기존 보유 수량을 자동 조정하지 않습니다.

현재 주문 가능 금액 비율은 실제 증거금 사용 후 남은 금액을 기준으로 하고 미사용 배정예산은 비율 기준에서 빼지 않습니다. 새 방식은 봇 예산 배정 기준이므로 수동 거래 증거금은 따로 차감하지 않습니다. 실제 주문은 거래소 주문 가능 증거금과 수수료·최소 주문 조건을 다시 확인합니다. 이 설정은 자금을 이체하거나 교차 포지션의 손실을 격리하는 기능이 아닙니다.

## 지갑 구간에 따라 USDT 예산 조정

단일·다중종목 봇의 예산 지정 방식에서 **지갑 증가 구간마다 예산 조정 · USDT**를 선택합니다. 시작 예산, 지갑 한 구간 금액, 한 구간당 예산 조정액을 USDT로 입력합니다. 기본 예시는 지갑 +200 USDT마다 예산 +10 USDT이며 원하는 금액으로 바꿉니다.

예를 들어 지갑 1,000 USDT에서 시작 예산 100 USDT를 등록하고 지갑이 한 번에 1,500이 되면 2구간을 적용해 목표 예산은 120, 구간 기준 지갑은 1,400이 됩니다. 남은 100은 유지되어 지갑이 1,600이 되면 예산이 130으로 증가합니다. 저장된 구간 기준과 예산은 서버 재시작 후에도 유지됩니다.

기본은 증액만 하며, 지갑이 줄어도 예산을 유지합니다. 감소 구간마다 예산도 줄이도록 별도 선택할 수 있습니다. 최소·최대 구간 예산을 정하고, 최대 0은 별도 상한 없음입니다. 미실현손익은 제외한 전체 USDT 선물지갑 기준이며 다른 봇·수동 매매의 확정손익과 입출금도 반영합니다. 이 봇의 손익을 별도로 다시 더하지 않습니다. 실제 주문은 기존 배정·가용 증거금 검사를 따르며 기존 보유 수량을 자동 변경하지 않습니다.

조건이나 이름만 저장하면 구간 기준을 유지합니다. 시작 예산이나 구간 설정을 변경하면 저장 시 현재 지갑에서 새로 시작합니다. 운용에 포함된 정지 봇도 지갑 구간을 반영합니다. 보관 중에는 구간을 누적하지 않고 운용으로 옮길 때 현재 지갑을 새 기준으로 잡되 기존 구간 예산은 유지합니다. 다중종목 봇은 부모에서 한 번 계산한 예산을 종목 비중으로 분배합니다. 기존 예산 방식은 자동 변경하지 않습니다.

지갑 구간 예산은 기본 설정의 **지갑 변동 기준 재설정** 또는 봇 ⋯ 메뉴에서 기준만 별도로 바꿀 수 있습니다. **현재 지갑 금액**으로 재설정하면 현재 늘어난 구간 예산은 유지하고 다음 한 구간부터 계산합니다. **금액 직접 지정**을 선택하면 해당 기준과 현재 지갑 사이의 완성된 구간을 바로 반영하며, 적용 전 기준·예산 변화·다음 증액 금액을 미리 보여줍니다. 예를 들어 현재 지갑 1,500 / 구간 예산 120 / 구간 200 / 조정액 10에서 기준을 1,500으로 바꾸면 예산은 120, 다음 증액은 1,700입니다. 기준을 1,000으로 지정하면 2구간을 반영해 예산은 140, 다음 증액은 1,600입니다. 기록·통계·보유 수량·운용 상태와 시작 예산 설정은 유지됩니다. 보관한 봇은 운용 복귀 시 그때의 지갑으로 기준을 다시 잡는 기존 규칙을 따릅니다.

## 사용자 지표 입력 통합

지표 목록의 **＋ 지표 만들기** 한 곳에서 작성합니다. `SMA(하이킨종가, 6)` 같은 계산식을 입력하면 선 하나를 그리고, `단기 = ...`와 `선("이름", 단기)`를 여러 줄로 입력하면 자동으로 변수와 출력선을 처리합니다. 별도 유형 선택은 없습니다. 기존 수식·스크립트 지표 수정도 같은 입력창을 사용하며 이름·색상·표시 위치·봉 주기 설정을 유지합니다. 예제와 데이터·함수 추가도 같은 창에 모았습니다. 목록에 저장한 뒤 ＋를 눌러 차트에 추가합니다.

## 지표 조건 화살표

**지표 → ＋ 지표 만들기**에서 선과 함께, 또는 화살표만 작성할 수 있습니다. 예제의 **골든·데드크로스 매수·매도 화살표**를 선택하면 바로 시작할 수 있습니다.

```text
단기 = VWMA(하이킨종가, 6, 거래량)
장기 = SMA(하이킨종가, 55)
선("단기", 단기)
선("장기", 장기)
매수신호("골든크로스", 상향돌파(단기, 장기))
매도신호("데드크로스", 하향돌파(단기, 장기))
```

매수신호는 기본 초록 ↑·캔들 아래, 매도신호는 빨강 ↓·캔들 위이며 **스타일**에서 각각 표시 여부·색상·위치·크기를 설정합니다. 화살표는 항상 가격 차트에 표시하며 지표 선은 선택한 표시 위치를 사용합니다. 신호 이름은 자유롭게 정합니다. 한 지표의 선·신호 출력은 합계 최대 6개입니다.

일반 조건은 참인 봉마다 표시하고, 상향돌파·하향돌파는 교차한 봉에서만 표시합니다. 진행봉 신호는 진행봉 값에 따라 나타나거나 사라질 수 있습니다. 조건 뒤 [1]을 붙이면 이전 봉의 조건을 현재 봉에 표시합니다. 예: 매수신호("이전 봉 골든", 상향돌파(단기, 장기)[1]). 신호는 차트 표시 전용이며 주문은 전송하지 않습니다. 실제 체결 B/S 표시와 독립적으로 동작합니다. 다른 기기에서도 저장한 지표를 사용할 수 있습니다.

## 조건 배경과 일반 화살표

지표 만들기에서 **배경("이름", 조건)**으로 조건이 참인 봉의 가격 차트 배경을 세로로 칠합니다. 스타일 탭에서 색상·투명도(0% 진하게~100% 투명)·표시 여부를 설정합니다. 상향돌파·하향돌파는 교차한 봉 한 칸만 칠하고, 단기 > 장기 같은 조건은 유지 구간을 연속해서 칠합니다. 배경은 선·신호 6개 한도와 별도로 최대 6개까지 추가합니다. 기존 지표의 배경은 자동 변경하지 않습니다.

**화살표("표시할 글자", 조건)**는 매수·매도에 한정하지 않는 표시 전용 신호입니다. 첫 번째 인수에 자유로운 글자를 쓰고, 빈 문자열 ""이면 글자 없이 표시합니다. 스타일에서 방향(↑/↓), 캔들 위·아래 위치, 색상·크기·쌓기 순서(0~99)를 설정합니다. 같은 봉·위치의 신호는 세로로 쌓이며 순서가 작을수록 봉 가까이에 놓입니다. 같은 순서면 지표 목록과 코드의 출력 순서를 따릅니다. 방향과 위·아래 위치는 서로 독립적입니다. 기존 매수신호·매도신호도 그대로 사용합니다.

```text
기울기20 = 변화율(SMA(SMA(하이킨종가, 20), 20), 1)
선("기울기20", 기울기20)
선("0 기준선", 0)
화살표("전환", 상향돌파(기울기20, 0))
화살표("확인", 상향돌파(기울기20, 0) and 하이킨종가 > 하이킨시가)
배경("상향 전환", 상향돌파(기울기20, 0))
배경("하향 전환", 하향돌파(기울기20, 0))
```

배경과 화살표는 실제 체결이나 주문이 아닙니다. 진행봉의 조건은 변할 수 있습니다. 조건 뒤 [1]은 이전 봉 조건을 현재 봉에 표시합니다. 새 봉이 추가됐다고 확정된 과거 조건을 미래 데이터로 다시 계산하지 않습니다. 예제 목록, 데이터·함수 삽입과 자동완성·인수 도움말에서도 사용할 수 있습니다. 배경은 클릭을 가로채지 않고 가격 범위를 바꾸지 않습니다. 화살표는 겹칠 때 잘리지 않도록 표시 여백을 확보합니다.

## 화살표·배경 표시 대상

지표 설정의 **스타일 → 각 화살표·배경 → 표시 대상**에서 **가격 차트 / 이 지표 패널**을 각각 선택합니다. 같은 지표의 일부 출력은 가격 차트에, 다른 출력은 보조지표 패널에 함께 표시할 수 있습니다. 기존 설정은 가격 차트 표시를 유지하며 수식 문법은 바뀌지 않습니다.

**이 지표 패널**을 선택하면 입력 탭의 표시 위치가 **별도 패널**로 바뀌고 해당 지표의 선도 그 패널에 표시합니다. 화살표는 **기준선**에서 기울기20·기울기6 등 어느 선을 따를지 고릅니다. 자동은 첫 번째 표시선을 사용하며, 표시선이 없으면 첫 번째 일반 선, 일반 선도 없으면 0을 기준으로 사용합니다. 명시적으로 선택한 선을 숨겨도 그 선의 값에 화살표를 표시합니다. 제거한 기준선은 자동으로 돌아갑니다.

같은 표시 대상·기준선·봉·위치의 화살표는 쌓기 순서대로 배치합니다. 배경은 선택한 패널 높이 전체를 칠합니다. 신호·배경만 있는 지표도 별도 패널을 만들 수 있습니다. 패널 표시를 사용하면서 입력의 표시 위치를 가격 차트 위로 바꾸면 저장 전에 별도 패널 선택을 안내합니다. 가격 차트에만 표시하려면 각 출력의 표시 대상을 가격 차트로 바꾸세요.

저장한 대상·기준선·방향·쌓기 순서·색상·투명도는 기기 공통으로 복원됩니다. 표시 위치 선택은 주문이나 봇 조건·예산을 변경하지 않습니다.
