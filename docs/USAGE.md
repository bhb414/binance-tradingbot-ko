# Futures Workroom

- 홈 차트는 마지막 조회 시장·종목·봉주기·일반/하이킨아시와 선택 범위를 브라우저의 `fw-chart-workspace-v1`에 저장합니다. 종목·시장·주기별 확대/이동 범위와 가격 축 자동/수동 범위·지표 패널 높이를 복원하고, 수평선은 종목·시장별로 저장해 다른 상품에 섞이지 않습니다. 최대 40개 조회 화면과 종목당 수평선 50개를 보존합니다. 기존 지표 설정·수식·색상·숨김과 지표 이름 접기는 기존 저장소를 계속 사용합니다. 같은 브라우저·주소에서 유지되며 브라우저 사이트 데이터를 지우면 초기화됩니다.

- 홈 주문의 **주문 귀속**에서 같은 종목의 봇 또는 **별도 주문 · 봇 외부**를 선택합니다. 다른 종목의 봇은 표시하지 않습니다. 봇 귀속 주문은 정지 중에도 진입·추가 진입·부분/전량 정리가 가능하며, 체결·예산·횟수·수수료는 해당 봇 원장에 반영합니다. 봇 운용예산과 보유 방향·거래소 주문 한도를 확인합니다. 미체결 일반 주문은 먼저 취소해야 하며, 정리 전 보호 주문의 취소·체결을 확인하고 남은 포지션의 보호 주문을 다시 구성합니다. 수동 지정가는 사용자가 취소하거나 체결할 때까지 지정한 유효기간을 따르며 봇의 시간 초과 시장가 전환을 적용하지 않습니다.
- 봇의 **정지**는 신규 진입만 중지하고 기존 포지션의 조건식 정리·TP/SL 관리를 유지합니다. 따라서 봇 포지션이 남은 종목을 별도 주문으로 변경할 수는 없습니다. 같은 종목·방향의 거래소 포지션은 합쳐지므로 해당 봇을 선택해 조절합니다. 봇 포지션·주문이 없고 신규 진입이 정지돼 있으면 같은 종목도 별도로 주문할 수 있습니다.
- 봇 모달 상단의 시작·정지 버튼은 현재 서버 상태를 표시하며, 편집 중인 설정을 저장하지 않고 저장된 조건으로 실행합니다. **상태·기록 → 보유 포지션**에서 수량·진입가·마크 가격·미실현손익·청산가를 보고 직접 추가 진입·부분/전량 정리·보호 설정으로 이동할 수 있습니다. 미체결 일반 주문의 잔량도 취소할 수 있습니다. 홈 포지션의 정리 버튼 역시 주문 귀속을 해당 봇으로 맞춥니다.
- 봇 손익은 **매매손익(비용 차감 전)**과 **순손익(확인된 USDT 수수료·펀딩 포함)**, 각각 기준 예산 대비 %를 표시합니다. 실현손익과 현재 미실현손익을 합산하며, 가져온 포지션은 인수 이후입니다. 펀딩은 원장의 보유 시점을 대조합니다. 조회 범위가 불완전하거나 비 USDT 비용·헤지 모드 등으로 귀속을 확정할 수 없으면 순손익을 미확인으로 표시합니다. 과거 펀딩 조회는 최대 89일로 제한하며 수수료를 두 번 빼지 않습니다. 홈 종목의 매매손익·순손익은 최근 30일 양방향 전체의 실현 기준이고, %는 현재 증거금 대비 참고율입니다. 과거 투자수익률과는 다릅니다.

바이낸스 상품 조회와 USDT 무기한 선물 봇을 제공하는 로컬 앱입니다. 공개 시세 조회, 계좌 연결, 수식 조건 평가와 주문 처리를 구현했습니다. 테스트넷·실전 계좌의 조회 연결을 확인했으며, **봇의 실제 주문·체결 검증은 남아 있습니다.**

## 실행과 첫 연결

Node.js 24 이상이 설치된 Windows에서 `run.cmd`를 실행하거나 이 폴더에서 `npm start`를 실행합니다. 추가 패키지는 필요하지 않습니다. 브라우저에서 [연결 설정](http://127.0.0.1:8896/#settings)을 엽니다. 연결 화면은 실전 계좌를 대상으로 하며 테스트넷 선택은 제공하지 않습니다. 서버는 이 PC의 `127.0.0.1`에만 바인딩하며, `PORT` 환경변수로 포트를 바꿀 수 있습니다.

1. 바이낸스 실전 계좌에서 본인이 발급한 **HMAC API Key와 Secret**을 연결 설정에 직접 입력합니다. 채팅에 키를 보내지 않습니다.
2. 계좌 조회만 확인하려면 주문 실행 허용을 끈 채 연결합니다. 잔고와 계좌의 단방향/헤지 모드를 자동 조회합니다. 계좌 모드를 임의로 변경하지 않습니다.
3. 주문을 진행할 때 연결 설정의 **실전 주문 허용** 토글을 켠 뒤, 봇 탭에서 종목·예산·레버리지·조건식·주문·익절/손절을 확인하고 해당 봇을 직접 시작합니다. 연결만으로 봇이 시작되지는 않습니다.

연결에 성공한 API Key와 Secret은 Windows DPAPI의 `CurrentUser` 범위로 암호화해 `.runtime/credentials.dpapi`에 저장합니다. 브라우저 저장소·일반 설정 원장·명령줄 인수에는 키를 저장하지 않습니다. 서버를 같은 Windows 사용자로 다시 실행하면 저장된 키로 계좌 조회를 자동 연결합니다. 주문 허용 토글은 같은 계좌·키의 마지막 설정을 복원합니다. 봇 신규 진입은 직접 시작합니다. 네트워크나 API 권한 때문에 연결하지 못하면 저장된 키를 유지하고 30초 간격으로 재시도하며, 설정에서 즉시 재연결할 수도 있습니다. 다른 Windows 사용자로 실행하거나 파일이 손상된 경우 앱에서 오류를 표시하고 새 키 등록을 받습니다.

설정의 **연결 해제·저장 키 삭제**는 저장된 암호화 파일과 메모리의 키를 제거합니다. 봇 소유 포지션·미해결 주문이 있으면 기존과 같이 삭제를 막습니다. 저장은 성공한 계좌 연결의 마지막 키 한 쌍과 해당 환경만 보관하며, 새 키 연결이나 암호화 저장이 실패하면 이전 키와 연결을 유지합니다. DPAPI는 같은 Windows 사용자 권한의 다른 프로그램까지 차단하지는 않습니다. [Microsoft DPAPI 설명](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.protecteddata)을 참고합니다. 출금·자금 이체 API는 사용하지 않습니다. 실전 주문 허용은 토글로 바로 변경하며 별도 확인 문구를 입력하지 않습니다. 끄면 봇 신규 진입과 조건식 매매·새 주문 전송이 중단되고, 기존 포지션·미체결 주문은 자동으로 취소하거나 청산하지 않습니다. 계좌 연결이 일시적으로 안 되어도 저장된 허용 설정을 끌 수 있습니다. 계좌 키 변경·저장 키 삭제 시에는 허용을 다시 선택합니다.

현재 앱은 폴더에서 실행합니다. 프로그램 폴더를 `.runtime`과 함께 삭제하면 로컬 키 저장 파일도 삭제되지만, `run.cmd`나 바로가기만 삭제하면 저장 파일은 남습니다. `WORKROOM_DATA_DIR`로 별도 데이터 폴더를 지정했다면 그 폴더를 별도로 정리해야 합니다. 설정의 **저장 위치 · 프로그램 삭제 시 처리**에 실제 저장 경로를 표시합니다. 로컬 저장본 삭제는 바이낸스에서 발급한 API 키를 취소하지 않으며, 발급 취소는 바이낸스 API 관리에서 별도로 해야 합니다.

## 구현한 기능

- 홈에서 바이낸스의 현재 거래 가능한 현물, USDⓈ-M 선물(주식·상품 선물 포함), COIN-M 무기한·만기 선물, 옵션을 전체/유형별로 검색합니다. 공개 시세는 계좌 접속 환경과 독립적인 실전 데이터이며 키 없이 OHLCV·호가·현재가를 조회합니다. 펀딩은 해당 데이터가 있는 선물에만 표시합니다. 거래 종료·만기 도래 상품은 목록에서 제외합니다.
- 관심 종목은 종목 찾기의 별로 추가/해제하고 **★ 즐겨찾기**에서 선택합니다. 같은 심볼의 현물과 선물을 별개로 저장하며 브라우저를 다시 열어도 유지합니다. 기존 6개 코인 목록을 기본 즐겨찾기로 사용하고 최대 500개까지 저장합니다. 호가 헤더의 검색 버튼으로 즐겨찾기를 바로 열 수 있습니다.
- 홈 오른쪽은 **호가 → 수동 주문** 순서입니다. 매수/매도 탭과 하나의 주문 버튼, 격리/크로스·레버리지, 지정가/시장가, BBO, 초기 증거금/주문 금액/수량 입력과 비율 슬라이더를 제공합니다. BBO는 매수에 매도 1호가, 매도에 매수 1호가를 입력합니다. Reduce Only는 매수로 숏 정리·매도로 롱 정리를 준비하며 실제 수량·설정을 다시 확인하는 모달을 거쳐야 전송됩니다. 현물·COIN-M·옵션·USDC 상품은 조회만 지원합니다.
- 주문창은 금액 입력과 단위 선택을 한 줄로 배치합니다. 주문 가능 잔액과 최대 주문금액·예상 증거금은 항상 표시하고, 잔액 행을 펼치면 선물지갑 잔고와 설명을, 예상 증거금을 펼치면 예상 주문금액을 표시합니다. 최근 수동 주문도 접고 펼칩니다. 잔액은 소수 둘째 자리까지 내림 표시하며 실제 주문 계산은 전체 정밀도를 유지합니다.
- 수동 주문은 연결한 계좌의 가격·규격·가용 증거금과 레버리지 구간을 사용합니다. 초기 증거금 입력은 선택 배수로 주문 금액을 산정하고 서버가 수량 단위·가용 잔고·1% 여유를 검사합니다. 비율 슬라이더는 진입 시 수수료 여유를 남긴 가용 증거금과 구간 한도, 정리 시 미체결 정리를 뺀 보유 수량 기준입니다. 보유·미체결이 있으면 증거금 모드·레버리지는 현재 값을 유지합니다. 봇 보유분은 주문 귀속에서 해당 봇을 선택해 조절합니다. 별도 주문은 봇 포지션·미체결 주문이 없고 신규 진입이 정지된 경우에 사용합니다.
- 주문 확인은 60초 뒤 만료되고 계좌·규격·가용 증거금·정리 가능 수량을 전송 직전에 다시 검사합니다. 정리 가능 수량은 미체결 정리 주문을 뺀 수량입니다. 주문 전 원장 저장과 고유 주문 ID를 사용하며 확인 번호를 재전송해도 같은 주문을 두 번 보내지 않습니다. 응답 유실·재시작 후에는 접수 상태를 조회하며 자동 재전송하지 않습니다. 이 앱으로 보낸 미체결 수동 주문은 주문창 아래에서 잔량을 취소할 수 있습니다. 설정 변경 중 실패하면 일부 계좌 설정이 반영됐을 수 있으므로 현재 설정을 다시 확인합니다.
- 포지션 종목을 누르면 홈 차트가 해당 USDT 선물 종목으로 전환됩니다. 현재 봉 주기·캔들 유형·지표 설정은 유지합니다. 홈 차트의 확대 버튼은 차트 모달을 엽니다. 일반/하이킨아시 캔들, 봉 주기, 범위 맞추기와 모달 전체화면을 지원합니다. 같은 심볼의 현물과 선물은 시장 구분으로 조회합니다. 계좌 연결 후 포지션·미체결 주문·봇 체결 내역을 표시합니다.
- 홈·모달의 **지표**에서 SMA·EMA·볼린저밴드·RSI·MACD·스토캐스틱·ATR·VWAP·거래량을 검색하고 최대 12개까지 추가합니다. 같은 지표도 여러 기간으로 추가할 수 있습니다. **추가된 지표** 목록 또는 차트 범례의 설정 버튼에서 입력·스타일·표시 범위를 편집하고 숨김·삭제할 수 있습니다. 추가된 목록에서 순서도 변경합니다. 기본 구성은 SMA 20/60·볼린저밴드·거래량이며 RSI 등은 독립 패널을 사용합니다.
- 지표별 기간·가격 소스·일반/하이킨아시/현재 차트 기준, 선별 색상·두께·선 종류·표시 여부, 차트 봉 주기별 표시 여부를 저장합니다. 표시 범위는 다른 시간대의 지표를 합성하는 기능이 아니라 해당 봉 주기 차트에서의 표시 설정입니다. 홈과 모달은 같은 지표 구성을 쓰며 이 브라우저의 로컬 저장소에 보존합니다. 차트 지표 설정은 봇 조건식을 변경하지 않습니다.
- 차트 위 지표 이름·값의 배경은 투명합니다. 목록 아래 **지표명 N** 버튼으로 이름·값과 관리 버튼만 접고 펼칠 수 있으며 지표 선과 별도 패널은 계속 표시합니다. 홈·확대 모달에 함께 적용되고 새로고침·종목·봉 주기 변경 후에도 접기 상태를 유지합니다.
- **지표 → 수식 만들기 → 수식 지표**에서는 이름과 숫자 수식을 입력하고 가격 차트 위/별도 패널을 선택합니다. `(종가[0]+종가[1]+종가[2])/3`과 `종가[0:3]/3`은 모두 현재 봉을 포함한 3봉 평균입니다. `[시작:끝]`은 시작부터 끝 직전까지의 과거 봉 값 **합계**이며 끝 번호는 제외합니다. `종가[1:4]`는 1·2·3봉 전의 합입니다. 구간은 최대 500봉이며 데이터가 부족한 봉은 빈 값입니다. 이 구간 문법은 조건식에서도 동일하게 계산합니다.

- **전체 주기 적용**은 수식의 모든 주기를 선택한 값으로 통일하고 기존 `[1]`, 구간 등의 위치는 유지합니다. `(종가[1] > 볼린저상단(종가, 20, 2)[1] AND RSI(종가, 14)[1] < 70)@5m`처럼 괄호 안의 지표가 공통 주기를 상속합니다. 직접 작성한 개별 `@1h`는 바깥 공통 주기를 덮어씁니다. ‘봉마다 한 번’은 수식의 가장 짧은 주기가 기준이며 봉을 쓰지 않는 상수·현재 포지션 조건은 1분 기준입니다. 예전 완성봉/진행봉 설정은 명시적인 주기와 인덱스로 한 번 변환합니다.
- 레버리지는 조건·행동 탭의 **롱·숏 진입 조건마다** 슬라이더와 숫자로 지정합니다. 연결한 계좌의 [종목별 레버리지 구간](https://developers.binance.com/docs/derivatives/usds-margined-futures/account/rest-api/Notional-and-Leverage-Brackets)을 조회해 종목 최대 배수와 예산 기준 한도를 표시하며 150배 구간도 지원합니다. 한도 초과 설정은 저장·시작·진입 시 검사합니다. 계좌 연결 전/조회 실패 시 슬라이더를 잠그고 숫자 설정은 보존합니다. 같은 종목의 롱·숏은 거래소 레버리지를 공유하므로 포지션이 없는 첫 진입에만 조건의 배수를 적용합니다. 보유 중 추가 진입은 현재 배수를 유지하며, 미래 진입 조건의 배수는 보유 중에도 편집할 수 있습니다. 실제 적용 응답·재조회가 확인되지 않으면 진입 주문을 보내지 않습니다. 편집 자체는 거래소 설정을 바꾸지 않습니다.
- 돌파 함수를 입력하면 첫 인수 A(돌파하는 값)와 두 번째 인수 B(기준값)를 구분하고 수식 아래에서 의미를 풀어 설명합니다. `상향돌파(A, B)`는 이전 봉 `A ≤ B`에서 현재 봉 `A > B`로 바뀌는 순간이며, `하향돌파(A, B)`는 이전 봉 `A ≥ B`에서 현재 봉 `A < B`로 바뀌는 순간입니다. 계속 위에 있는 상태를 비교할 때는 `A > B`를 사용합니다.
- 조건·행동 탭에서 조건마다 롱 진입·숏 진입·롱 정리·숏 정리·전체 정리를 지정합니다. 각 조건에 봉 주기·수식·사용 여부·주문 비율·시장가/지정가·호가·미체결 처리·재실행 기준을 따로 설정합니다. 조건은 20개까지 추가하고 순서를 변경할 수 있습니다. 진입 비율은 봇 예산 기준, 정리 비율은 해당 봇의 보유 수량 기준이며 전체 정리는 100%입니다.
- 한 봇은 한 시점에 한 방향을 보유합니다. 보유 중 같은 방향의 추가 진입은 가능하며 반대 방향의 진입은 기존 포지션을 정리한 뒤 가능합니다. 정리 조건이 진입보다 우선하고, 같은 종류는 위에서 먼저 충족된 조건 하나를 처리합니다. 포지션이 없을 때 롱·숏 진입 조건이 동시에 충족되면 진입을 보류합니다. 정리 행동은 포지션이 없거나 보유 방향이 다르면 실행하지 않습니다.
- 서버가 약 3초 주기로 조건과 주문을 확인합니다. 시장가/지정가, 매수·매도 호가/현재가 기준, 틱 가감, Post-only, 지정가 대기시간, 미체결 잔량 취소 또는 시장가 전환을 처리합니다. REST 폴링 방식이며 초단타용 체결 지연을 보장하지 않습니다.
- 종목별 수량·가격 단위와 주문 최소 금액, 계좌 가용 증거금, 배정 예산, 레버리지 한도, 크로스/아이솔레이트 설정을 검사합니다. 진입 산정 시 요청 증거금의 1%를 수수료·반올림 여유로 남깁니다. 이 여유는 최대 수수료나 슬리피지를 보장하지 않습니다.
- **포지션당 진입 횟수**는 처음 진입과 추가 진입의 체결 횟수이며 전량 정리하면 0회로 돌아갑니다. 새 봇은 제한 없음(내부 값 `0`)이 기본이고 1~20회 제한도 선택합니다. 기존 봇의 제한은 그대로 유지합니다. 부분 체결·잔량 시장가 전환은 같은 논리적 진입 1회로 셉니다. 횟수 제한이 없어도 예산·잔고·신호 재실행·미해결 주문 검사는 유지합니다.
- **같은 조건 재실행**의 조건 재성립/봉당 1회/시간 간격을 선택합니다. **같은 조건 재실행 간격**은 시간 간격 방식에만 적용하며 0초면 감시 주기마다 실행할 수 있습니다. **전량 정리 후 새 진입 대기**는 별도 값이며 0초면 추가 대기가 없습니다. 기존 합쳐진 값은 두 설정에 같은 시간으로 옮겨 이전 동작을 유지하고, 새 봇의 청산 후 대기는 0초입니다. 고유 주문 ID와 주문 의도를 디스크에 먼저 기록합니다. 응답이 불명확하면 재전송하지 않고 거래소에서 접수 여부를 조회합니다. 부분 체결된 지정가는 취소 확인 후 잔량만 전환합니다.
- **익절 TP 사용 / 손절 SL 사용**을 각각 선택합니다. 기존 봇은 사용 여부가 없으면 둘 다 켜진 것으로 취급하며 새 기능을 추가해도 자동으로 끄지 않습니다. 켜 둔 항목만 봇 보유 수량에 맞는 거래소 Algo 주문으로 등록하고 체결·반대 주문 취소를 추적합니다. 둘 다 끄면 거래소 TP/SL과 로컬 가격 비율 청산을 모두 중지하고 조건·행동 탭의 정리 조건을 사용합니다. 정리 조건이 없으면 자동 정리하지 않습니다. 조건식 정리는 프로그램과 주문 실행이 켜져 있는 동안 동작합니다.
- 보호 주문을 끄는 설정을 저장하면 주문 실행이 허용된 상태에서 기존 봇 소유 주문을 취소하고 완료 여부를 확인합니다. 조회 전용에서는 거래소 주문을 바꾸지 않으며 주문 허용 후 반영합니다. 취소가 불명확하면 확인 대기를 표시하고 새 진입을 보류합니다. 외부 수동 보호 주문은 자동 인수·취소하지 않습니다. 활성 보호 주문의 가격 기준은 마크 가격(거래소 평가 가격) 또는 최종 체결가(최근 실제 거래 가격)이며 조건식의 종가·하이킨아시 계산을 바꾸지 않습니다.
- 봇 일시정지는 신규 진입을 중지하고 진입 미체결을 취소하며, 보유 포지션의 정리 조건과 사용 중인 보호 주문 관리는 유지합니다. 전량 청산은 해당 봇이 소유한 수량에만 적용합니다.

## 포지션 정보와 관리

홈 포지션은 **종목마다 한 행인 표**로 표시합니다. 손익·ROI와 금액·수량을 묶어 표시하고 종목 열을 고정합니다. 넓은 화면에서는 관리 버튼도 오른쪽에 고정하며, 화면이 좁으면 표 안에서 좌우로 넘겨 전체 정보·관리 버튼을 확인합니다. 시세가 갱신돼도 표의 가로 스크롤 위치를 유지합니다.

홈 포지션은 방향·증거금 모드·배수, 미실현손익·ROI, 포지션 금액·증거금·증거금 비율, 진입가·마크가·청산가를 표시합니다. 크로스 증거금 비율은 USDT 크로스 계좌의 담보를 공유하는 값이며, 격리는 해당 포지션의 유지 증거금/격리 증거금 잔고입니다. **실현손익 · 최근 30일**은 같은 종목의 양방향 USDT 실현 매매손익 합계이며 수수료·펀딩은 제외합니다. 옆의 순손익에는 같은 기간의 실제 USDT 수수료·펀딩을 반영하며, 각 %는 현재 증거금 대비 참고율입니다. API 조회가 불완전하면 금액을 꾸미지 않고 `—`로 표시합니다. 해당 조회는 60초 캐시와 시간 구간 분할·중복 제거를 사용합니다. [거래소 실현손익 조회](https://developers.binance.com/docs/derivatives/usds-margined-futures/account/rest-api/Get-Income-History)를 사용합니다.

**봇에 맡기기**는 포지션 행 오른쪽 관리 열에 배치합니다. 이미 봇이 소유한 포지션은 봇 설정/관리 내역으로 연결하며, 수동 포지션의 **정리 주문**은 같은 종목의 주문창에 방향·Reduce Only·수량을 준비합니다. 준비만으로 주문하지 않습니다.

## 저장과 재시작

설정·주문 의도·체결·활동 기록은 `.runtime/state.json`에 저장합니다. 파일 교체 전에 저장 내용을 디스크에 동기화하며 저장 실패 시 새 주문을 차단합니다. 이 디렉터리와 `.env`는 Git에서 제외합니다. `WORKROOM_DATA_DIR`로 저장 경로를 지정할 수 있습니다.

재시작하면 봇 신규 진입은 일시정지되고, 저장된 주문 허용 설정과 같은 계좌 연결은 자동 복원됩니다. 주문 허용이 켜져 있으면 보유 포지션의 조건식 정리·보호 주문 관리가 이어집니다. 이전 포지션·미해결 주문 원장은 유지됩니다. 거래소에 접수된 보호 주문은 서버 종료 시 자동 취소하지 않습니다. 프로그램이 꺼진 동안에는 로컬 조건 감시·주문 조정이 실행되지 않습니다. 포지션이나 미해결 주문이 남으면 계좌 변경·연결 해제·봇 삭제·매매 설정 변경을 제한합니다.

기존 화면 데모의 브라우저 설정은 서버 설정으로 한 번 옮기되, 예시 잔고·손익·보유 수량은 옮기지 않습니다. 옮긴 봇은 모두 신규 진입 일시정지 상태입니다. 초기 예시 전략의 수익성은 검증하지 않았습니다.

이전 고정 방향의 진입 조건은 같은 방향·수식·주문 설정의 조건·행동으로 자동 변환합니다. 새로 보이는 반대 방향과 정리 조건은 사용을 끈 상태로 추가하며, 별도의 수식 입력 후 사용을 켭니다. 조건별 실행 기록은 재시작 후 유지됩니다. 신규 진입 중지 시 정리 조건과 보호 주문 관리는 계속되며, 취소한 진입 잔량의 시장가 전환 계획은 폐기합니다.

## 현재 제약과 계산 기준

- 인증된 계좌 조회와 실제 테스트넷 주문·부분 체결·취소·보호 주문의 종합 검증은 사용자 키 연결 후 필요합니다. 자동 테스트는 모의 거래소로 주문 흐름을 검증합니다. 백테스트는 제공하지 않습니다.
- 봇 자동주문은 일반 USDT 증거금 무기한 선물을 지원합니다. 주식·상품 선물, 현물, COIN-M, 옵션은 이번 변경에서 조회를 지원하며 봇 자동주문 지원을 확장하지 않았습니다. Portfolio Margin·다중 자산 담보 계좌는 검증하지 않았습니다. 같은 종목을 여러 봇이나 수동 거래와 나누어 운용하지 않습니다.
- SMA·돌파·과거 인덱스 등 과거를 계산하는 연산 전체를 한 주기 안에 둡니다. `상향돌파(종가, EMA(종가, 20))@5m`이 올바른 예입니다. 시간축이 다른 값들을 함수 안에서 과거로 되감는 표현은 향후 봉의 완성 가격이 섞이지 않도록 거절합니다. 데이터의 주기를 생략하면 수식에 표시되는 공통 `(...)@5m` 범위가 필요합니다. 이전 `봉()/frame()`은 사용하지 않습니다. 차트 수식 지표는 현재 차트 주기만 사용하며 `@`는 봇 조건에서 지원합니다. `종가`는 일반 봉, `하이킨종가`는 합성 봉으로 고정합니다.
- 하이킨아시는 합성 가격입니다. 볼린저는 모집단 표준편차, EMA는 SMA 초기값, RSI는 Wilder 방식입니다. 수식의 수익률은 가격 변동률에 레버리지를 곱한 값이며 수수료·펀딩을 제외합니다.
- 봇 손익은 확인된 체결의 매매 손익과 USDT 수수료, 계좌에서 조회한 평가 손익을 합칩니다. 펀딩과 USDT 이외 자산으로 낸 수수료는 포함하지 않습니다. 봇 예산은 주문 산정 한도이며 크로스 계좌의 최대 손실 한도가 아닙니다.


- API 429/418 호출 제한과 일시적 시세·계좌 조회 실패는 **자동 재개 대기**로 표시합니다. 시작 상태와 기존 조건 신호 기록을 유지하고, 지정된 대기 시간이 지나면 주문 접수·계좌 상태를 먼저 확인한 뒤 감시를 재개합니다. 사용자가 정지한 봇은 자동 시작하지 않습니다. 대기 중에는 새 조건 판단을 하지 않으므로 프로그램이 실행하는 진입·청산이 늦어질 수 있습니다. 이미 거래소에 정상 등록된 TP/SL은 거래소에서 계속 관리합니다. 권한·설정·원장 불일치·접수 불확실 등 확인이 필요한 오류는 기존 중지 처리를 유지합니다.
- 차트와 봇은 같은 시장의 요청량·호출 제한 대기를 공유합니다. 사용량 응답 헤더를 반영해 일반 조회는 한도의 75%부터 조절하고 계좌 확인·주문을 위한 여유를 남깁니다. 반복 봉 조회는 최근 3개 봉만 갱신해 기존 1,000봉 이력을 유지하며, 연결 공백으로 이력이 이어지지 않으면 전체를 다시 조회합니다. 다른 프로그램이 같은 IP를 쓰는 경우도 거래소 사용량에 포함됩니다.

## 검증과 출처
